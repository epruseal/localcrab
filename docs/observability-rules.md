# 제품 관측 기록 규칙

## 목적과 적용 범위

제품 코드를 추가하거나 변경할 때는 의미 있는 사용자 작업의 시작과 종료, 주요 내부 단계, 결과와 실패를 연결할 수 있는 관측 경계를 설계한다. 기록은 실제 사용자 경험과 내부 지연의 원인을 분리할 수 있어야 한다. 함수마다 로그를 추가하지 않는다. 제품 변경이 기존 경계를 그대로 쓰고 새로운 관측 요구가 없다면 그 이유를 변경 설명에 적는다.

현재 검색 trace는 선택적 합성 baseline 실행에서 제품 검색 함수를 계측한다. 이 경로는 운영 MCP 요청의 상시 수집이나 사용자 수신 시간, 네트워크 및 SQLite native 내부를 관측하지 않는다. 아래 규칙은 앞으로 제품 코드를 설계할 때의 요구다. 현재 구현의 완성이나 운영 배포를 주장하지 않는다.

## 기록 경계와 내용

- 사용자 작업, 재시도와 주요 단계에 식별자를 둔다. 각 단계는 부모 작업 및 해당 요청과 연결한다. 병렬 단계와 스레드의 관계를 실제 호출 경계에 맞춰 기록한다.
- 단조 시계를 사용해 시작과 종료를 기록한다. 결과는 실제 반환과 대조한다. 실패와 취소는 정상 종료와 구분한다. 재시도와 표본의 채택 또는 제외 사유를 기록한다.
- 기록하지 않은 구간과 관측 단위의 한계를 명시한다. 측정하지 않은 시간을 특정 원인으로 단정하지 않는다. 시스템 집계 수치를 개별 요청 대기로 오인하지 않는다.
- 기록이 꺼진 상태에서 제품의 반환값, 순서, 경고, 예외와 취소 처리를 바꾸지 않는다. 관측 오류가 원래 작업의 예외를 대체하지 않도록 한다.

## 정보 보호와 용량

- 입력 원문, 예외 원문, 자격증명, 개인정보와 팩 내용을 기록하지 않는다. 필요한 구분은 정제된 식별자, 고정된 상태 코드와 집계값으로 한다. 식별자가 민감 정보를 복원하지 않는지도 확인한다.
- 이벤트와 표본의 용량을 제한한다. 초과나 누락이 발생하면 incomplete로 표시한다. 일부만 남은 기록을 완전한 기록으로 게시하거나 재생하지 않는다.
- 기록 게시, 정리 또는 무결성 검증에 실패하면 관측 결과를 성공으로 보고하지 않는다. 원래 제품 작업의 실패와 관측 게시 실패를 구분한다.
- 회전과 보존은 별도 승인된 정책을 따른다. 현재 합성 검색 trace 묶음에 logrotate 적용이 완료됐다고 가정하지 않는다.

## 스키마와 검증

- 기록 스키마에 버전, 소유 식별, 요청과 단계의 연결, 상태 및 불완전 여부를 정의한다. 생산자와 소비자가 기대하는 모드를 명시한다. 일반 기록을 더 엄격한 기록의 성공으로 대신하지 않는다.
- 검증기는 시작과 종료, 부모 범위, 요청과 시도의 연결, 표본의 중복과 누락, 시각 및 분류를 대조한다. 실제 호출이나 독립 관측과 원장을 대조한다. 원장 자신의 목록만으로 완전성을 증명하지 않는다.
- 검증된 기록만 재생한다. 손상, 누락, 게시 실패, 용량 초과와 모드 불일치의 대조군을 확인한다. 저장 무결성과 의미 검증은 각각 확인한다.
- 새 코드나 기존 코드의 관측 경계가 바뀌면 같은 변경에서 이 문서와 해당 스키마, 실행 레시피와 시험을 갱신한다. 변경이 필요 없는 항목은 기존 계약을 확인하고 변경 설명에 근거를 적는다.
