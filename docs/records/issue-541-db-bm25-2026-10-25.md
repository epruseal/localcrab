# #541 DB BM25 색인 측정 기록 (2026-10-25)

이 기록은 2026-10-25에 관측한 값이다. 갱신하지 않는다. 설계와 재현 절차는 `docs/issue-541-db-bm25.md`에 있다.

## 착수 전 probe: 색인 배치 비교

- 입력: `scripts/search_corpus.py generate --preset S1 --seed 542`의 문서 20150개를 하네스 행 계약과 비슷한 노드 dict로 바꾼 목록. 팩 ID는 코퍼스의 값을 그대로 썼다.
- 실행: transient systemd 서비스(`CPUQuota=100%`, `Nice=19`, `LimitAS=2G`, `MALLOC_ARENA_MAX=2`). 8GB RAM, 4코어 aarch64, SQLite 3.46.1.
- 방법: 두 배치에 같은 토큰 열을 넣고, 같은 Python BM25 식으로 질의 세트 42개의 전체 점수 목록을 계산해 `BM25Index`(같은 노드 전량)와 비교했다.

| 항목 | 맞춤 역색인 표 | FTS5 contentless |
|---|---|---|
| 점수 불일치(질의 42개, 두 배치 합) | 0 | 0 |
| 색인 바이트(`dbstat`) | 역색인 약 51.1MB, 문서 표 약 25.0MB(용어 목록 포함) | FTS 약 12.3MB, 문서 크기 표 약 0.25MB, 문서 표 약 1.1MB |
| 노드 검색 본문(`_node_text` UTF-8) 대비 | 약 4.0배 | 약 0.73배 |
| 구축(토큰화 제외) | 16.8초 | 1.7초 |
| 질의 42개 BM25 계산 합 | 12ms | 14ms |
| 모든 문서에 있는 토큰 하나, 모든 팩 | 59ms | 58ms |

같은 질의 42개를 기존 메모리 색인(`BM25Index.search`, 결과 상한 없음)으로 계산한 합은 8062ms였다. 토큰화는 2.43초, 토큰 총수는 5070847개, 고유 (문서, 용어) 쌍은 2551736개였다. FTS5 배치에서 문서 2000개를 지운 뒤 표본 용어 3219개의 `fts5vocab` 문서 빈도와 지운 문서의 출현 수가 다시 계산한 값과 모두 같았다.

## 착수 전 probe: SQLite 동작

- `BEGIN IMMEDIATE` 안의 `CREATE TABLE`, `CREATE VIRTUAL TABLE ... fts5`, `CREATE TRIGGER`는 되돌리면 하나도 남지 않았다. 중간 DDL이 실패한 트랜잭션도 되돌린 뒤 객체가 남지 않았다.
- 트리거 안의 `INSERT OR IGNORE`는 바깥 문장이 upsert(`ON CONFLICT DO UPDATE`)일 때 같은 키 두 번째 넣기에서 `UNIQUE constraint failed`로 실패했다. `INSERT ... SELECT ... WHERE NOT EXISTS` 형태는 upsert, `INSERT OR REPLACE`, 키 변경 UPDATE에서 모두 맞는 키를 남겼다.
- FTS5는 32768바이트보다 긴 용어를 32768바이트로 잘랐고, 한글 긴 토큰은 UTF-8 문자 중간에서 잘려 용어를 읽을 때 디코드 오류가 났다. 1024바이트를 넘는 토큰을 대리 용어로 바꾸면 여러 문자 체계를 섞은 표본과 긴 토큰의 왕복 불일치가 0이었다.
- Python sqlite3에서 명시 `BEGIN` 뒤의 읽기는 다른 연결의 커밋 뒤에도 같은 스냅숏을 보았다.
