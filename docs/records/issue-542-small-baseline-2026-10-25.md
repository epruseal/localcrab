# #542 소형 기준선 측정 기록 (2026-10-25)

이 기록은 2026-10-25에 관측한 값이다. 갱신하지 않는다. 판정 기준과 재현 명령은 `docs/issue-542-search-baseline.md`에 있다. 다음 측정은 새 날짜의 기록으로 남긴다.

## 조건

- 코드: 이 기록을 더한 브랜치의 부모 커밋. 기존 검색 코드는 base(`origin/main`)와 같다.
- 코퍼스: `scripts/search_corpus.py generate --preset S1 --seed 542`(생성기 버전 1). 노드 20150, source 형태 5136, 질의 42(종류 14 x 3).
- 실행: transient systemd 서비스(`CPUQuota=100%`, `Nice=19`, `LimitAS=2G`, `MALLOC_ARENA_MAX=2`, `PYTHONDONTWRITEBYTECODE=1`). 보고서의 `environment`에 주소 공간 상한 2GiB와 cgroup `cpu.max` `100000 100000`이 남았다.
- 장치 등급: 8GB RAM, 4코어 aarch64. 측정은 한 번에 하나씩 순차로 했다.
- 반복: 질의마다 데우기 1회 뒤 5회. 동시 쓰기는 초당 5건, 60초, 300건.
- 적재: 37.1초, 적재 프로세스 peak RSS 약 149MiB. 적재 뒤 관측 상태가 코퍼스에서 계산한 기대 상태와 다섯 표 모두 일치했다.

이 기록의 값은 구현 검증 1회차 지적을 반영한 하네스로 다시 측정한 두 실행의 값이다. 그 전의 측정은 증거로 쓰지 않는다. 수정 전후 두 설정 모두 질의별 레그 분류와 자동 선택 판정에 바뀐 것이 없었다.

## 실행 판정

두 설정 모두 `verdict: COMPLETE`이고 세대가 바뀌어 버린 묶음은 0이다. warm 모든 반복(질의 42 x 5회 x 레그 넷)의 독립 결함 표지에서 누출, 중복, 범위 오류, 경고 누락이 0이다. 동시 쓰기 구간의 결합 결과(기본 190건, 축소 437건)에서 누출과 중복이 0이다. 동시 쓰기 구간은 결합 결과만 얻으므로 다른 판정은 하지 않았다.

## 품질 (질의 42건, 마지막 반복의 분류)

| 레그 | 기본 설정 | 축소 상한(행 상한 5038) |
|---|---|---|
| BM25 | pass 41, partial_silent 1 | pass 15, partial_flagged 27 |
| FTS | pass 42 | pass 42 |
| vector | pass 42 | pass 42 |
| 결합 | pass 40, partial_silent 1, miss 1 | pass 30, partial_flagged 11, miss 1 |
| 자동 선택 오류 | 0 | 1 |

두 설정 모두 warm 모든 반복의 분류별 수(`summary.repeat_classes`)는 위 마지막 반복 분류별 수의 정확히 5배였다. 기본 설정의 조용한 부분 결과 표지 10건은 아래 `top-k-pressure-1` 한 질의가 BM25와 결합에서 다섯 반복 모두 받은 것이다.

### 기본 설정에서 확인한 실패

- `top-k-pressure-1`: BM25가 정답을 상위 10에 넣지 못했고 coverage 경고가 없다(`partial_silent`). 정답은 BM25 결과 41건 가운데 41위였고 비정답 대조군 40건이 모두 앞에 있었다. 결합 결과도 정답을 놓쳤다. vector는 이 정답을 보충하지 못했다.
  - 근본원인은 BM25 길이 정규화다. 정답 노드 텍스트는 1670자이며 한글 n-gram 확장 뒤 토큰 722개다. 색인 평균은 248.2개다. 정답은 희귀 토큰(df 2, idf 9.009)과 흔한 토큰(df 42, idf 6.176)을 한 번씩 가진다. 대조군은 토큰 175개에 흔한 토큰만 5번 가진다. 같은 색인에서 정답 점수 8.1677, 대조군 점수 12.5161이었다. 이 점수는 같은 실행 디렉터리의 색인을 별도 스크립트로 계산한 값이다.
  - 같은 종류의 `top-k-pressure-0`과 `top-k-pressure-2`는 통과했다. 실패는 정답 문서가 평균보다 길 때 나타난다.
- `long-tail-1`: 노드 형태 문서의 표지 토큰이 노드당 토큰화 글자(65536) 뒤에 있다. BM25 계약 밖이고 source 행이 없어 FTS도 찾지 못한다. 결합 `miss`다.
- freshness: BM25의 수정 반영 14.923초와 삭제 반영 15.413초가 요구치 10초를 넘었다. 새 문서 반영은 6.506초였다.

### 축소 상한 설정에서 확인한 실패

- 창 밖 정답 때문에 BM25가 27건에서 정답을 놓쳤고, 모두 coverage 경고와 함께 나왔다(`partial_flagged`). 조용한 누락은 0이다. 결합 결과는 그 가운데 11건에서 정답을 놓쳤다. 나머지는 FTS나 vector가 보충했다.
- `auto-content-1`: 정답은 소형 팩의 노드 형태 문서이고 창 밖에 있다. 콘텐츠 probe가 아무 팩도 고르지 못해 `auto_pack_below_threshold`로 전체 읽기 범위를 검색했다(`wrong_pack`).
- `top-k-pressure-1`은 여기서 `partial_flagged`다. 정답이 창 밖이기도 해서 coverage 경고가 붙는다. 기본 설정의 순위 실패가 경고 뒤에 가려진다.
- 팩을 지정하지 않은 질의(전체 범위와 자동 선택 실패 뒤의 전체 범위)에는 `BM25 coverage missing requested pack ids`에 주체의 빈 기본 팩이 나온다. 기본 설정에서는 이 경고가 없다.
