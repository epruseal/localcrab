# #556 결합 결과의 어휘 레그 1위 보장 측정 기록 (2026-10-26)

이 기록은 2026-10-26에 관측한 값이다. 갱신하지 않는다. 설계와 판정 근거는 `docs/issue-556-fusion.md`에 있다.

## 1. 착수 전 진단: rerank 입력과 출력

- 입력: `scripts/search_corpus.py generate --preset S1 --seed 542`로 만든 코퍼스를 base(`origin/main`, #550 포함)의 `scripts/search_baseline.py load`로 적재했다. 적재는 `COMPLETE`였다(노드 20150, source 형태 5136).
- 실행: transient systemd 서비스(`CPUQuota=100%`, `Nice=19`, `IOSchedulingClass=best-effort`, `IOSchedulingPriority=7`, `LimitAS=2G`, `MALLOC_ARENA_MAX=2`, `PYTHONDONTWRITEBYTECODE=1`). 8GB RAM, 4코어 aarch64. 한 번에 하나씩 돌렸다.
- 방법: 적재 디렉터리의 사본에서 하네스와 같은 `resolve_packs`와 `HybridQuery.query`(기본 설정, `limit` 10)를 불렀다. 프로세스 안에서 `Reranker.rerank`를 감싸 입력 레그 목록과 전체 출력을 기록했다. 저장소 파일은 바꾸지 않았다.
- 결과(`top-k-pressure-1`): 레그 결과는 vector 40건(대조군 9), BM25 41건(대조군 40), FTS 8건(대조군 8)이었다. 정답은 BM25 1위였고 vector와 FTS에는 없었다. rerank 출력 72건 가운데 정답은 39위(점수 0.3809)였다. 상위 15건은 모두 대조군이었다. 상위 3건은 세 레그, 다음 11건은 두 레그, 15위는 BM25 한 레그에 나왔다. 1위 점수는 1.08이었다.

## 2. 착수 전 probe: 후보 비교

- 방법: 같은 적재 디렉터리의 새 사본에서 질의 42개마다 후보별 결합 결과를 계산했다. 후보는 프로세스 안에서만 적용했다(reranker 감싸기, 또는 접기 함수 감싸기로 접기 뒤 재배열). 저장소 파일은 바꾸지 않았다.
- 1차 probe의 후보: 현행, 어휘 레그(BM25, FTS) 1위 보장, 모든 레그 1위 보장, BM25 레그 1위 보장, BM25 레그 RRF 가중 2배와 3배(BM25 목록을 RRF 누적에 반복해 넣음), 교차 점수에 후보 집합 idf.
- 1차 probe의 보장 후보는 옮긴 결과를 레그 순서로 놓았다. 이 코퍼스에서 옮긴 결과는 질의마다 하나뿐이었으므로 2차 probe의 규칙(원래 순서)과 결과가 같다.
- 2차 probe의 후보: rerank 경로의 현행, 어휘 레그 1위 보장, 어휘 레그 상위 2 보장, 평면 병합의 현행, 평면 병합의 어휘 레그 1위 보장. 보장 칸은 창 크기의 절반(내림)까지이고, 옮긴 결과는 원래 순서대로 창의 끝 칸에 놓았다.

결합 상위 10이 현행과 달라진 질의와 결합 must-hit 누락 질의는 다음과 같다. 모든 후보에서 중복은 0이었다.

| 경로와 후보 | 순서가 바뀐 질의 | 결합 누락 질의 |
|---|---|---|
| rerank 현행 | 해당 없음 | `top-k-pressure-1`, `long-tail-1` |
| rerank, 어휘 레그 1위 보장 | `top-k-pressure-1` | `long-tail-1` |
| rerank, 어휘 레그 상위 2 보장 | `top-k-pressure-1` | `long-tail-1` |
| rerank, BM25 레그 1위 보장 | `top-k-pressure-1` | `long-tail-1` |
| rerank, 모든 레그 1위 보장 | `top-k-pressure-1`, `top-k-pressure-2` | `long-tail-1` |
| rerank, BM25 RRF 가중 2배 | `top-k-pressure-0`, `top-k-pressure-2` | `top-k-pressure-1`, `long-tail-1` |
| rerank, BM25 RRF 가중 3배 | `top-k-pressure-0`, `top-k-pressure-2` | `top-k-pressure-1`, `long-tail-1` |
| rerank, 교차 점수 후보 집합 idf | `korean-variant-0`, `top-k-pressure-0`, `top-k-pressure-2` | `top-k-pressure-1`, `long-tail-1` |
| 평면 병합 현행 | 해당 없음 | `auto-content-0`, `auto-content-2`, `explicit-mixed-1`, `long-tail-1` |
| 평면 병합, 어휘 레그 1위 보장 | `auto-content-0`, `auto-content-2`, `explicit-mixed-1`, `auto-title-0`, `top-k-pressure-1` | `long-tail-1` |

- `long-tail-1`은 정답 표지 토큰이 노드당 토큰화 글자 뒤에 있는 노드 형태 문서다. 어느 레그도 찾지 못하므로 모든 후보에서 누락이다(#542 기준선 기록과 같다).
- 모든 레그 1위 보장에서 `top-k-pressure-2`에 들어온 결과는 vector 1위이며 정답도 대조군도 아니다.
- rerank 어휘 레그 1위 보장의 `top-k-pressure-1`: 정답이 10위에 왔고 그 앞의 9건은 대조군이다. 밀려난 10위 결과는 대조군이다.
- 평면 병합 현행의 세 누락(`auto-content-0`, `auto-content-2`, `explicit-mixed-1`): 정답은 BM25 1위다(앞의 둘은 FTS 1위이기도 하다). 평면 병합이 vector 레그의 정규화 점수를 남겨 창 밖에 두었다. 보장 뒤 세 정답 모두 10위에 왔다.
- 평면 병합 보장의 `auto-title-0`은 정답이 없는 팩 선택 질의다. 끝 칸에 BM25 1위가 들어왔다. `top-k-pressure-1`은 정답이 2위로 그대로이고 끝 칸에 FTS 1위(대조군)가 들어왔다.

## 3. 구현 뒤 재현 시험과 역변이

- RED: 구현 전 코드에서 새 시험 가운데 `HybridQuery.query`를 거치는 세 시험(rerank 재현, 평면 병합, `limit` 1 경고)을 임시 사본으로 돌렸다. 세 시험 모두 기대한 이유로 실패했다(rerank 결과에 정답 없음, 평면 병합 끝 칸이 정답 아님, `fusion:` 경고 없음).
- 역변이: 폐기용 checkout에서 변이마다 `tests/test_query_lexical_reservation.py`를 돌렸다. `_reserve_leg_tops` 호출을 지운 변이는 rerank 재현, 평면 병합, `limit` 1 경고 시험이 실패했다. 창 안 1위를 보호 집합에 넣지 않는 변이(첫 설계의 규칙)는 창 안 1위 보호 시험이 실패했다. 창 밖 수를 옛 창에서 세는 변이는 rerank 재현, 평면 병합, 창 안 1위 보호, 접기 시험이 실패했다. 변이를 되돌린 대조군은 전부 통과했다.

## 4. 구현 뒤 전체 스위트 대사

- 코드: base는 `origin/main`(이 브랜치의 분기점)이고 별도 detached worktree에서 돌렸다. head는 이 브랜치의 구현 커밋이다.
- 실행: `docs/gate-recipes.md` 6절의 재현 명령을 transient 서비스 안에서 base, head 순으로 하나씩 돌렸다. 실행 중 주 PID에서 주소 공간 상한 2147483648바이트와 cgroup `cpu.max` `100000 100000`을 확인했다. `OPENCRAB_PG_TEST_URL`은 두 실행 모두 두지 않았다. 공유 PostgreSQL 컨테이너를 쓰지 않기 위해서이며, 두 실행이 같은 PG 시험을 똑같이 건너뛴다.
- 결과: 두 요약 모두 `VERDICT:COMPLETE`. base는 tests 8875, skipped 508, 실패 6이다. head는 tests 8885, skipped 508, 실패 6이다. 실패 id 집합은 같다(`tests/test_issue80_sql_graph.py`의 PG와 Neo4j 런타임 시험 여섯 개. #550 기록 3절과 같은 필수 환경 변수 누락이다). 상태 대조에서 바뀐 항목은 `tests/test_query_lexical_reservation.py`의 새 시험 10개 추가(모두 pass)뿐이다.
- CI 기본 환경: 사용자 이름을 별도로 두고 기본 basetemp(시스템 임시 디렉터리)로 새 시험 파일과 `test_query_characterization.py`, `test_query_duplicate_fold.py`, `test_query_retrieval.py`, `test_search_baseline.py`, `test_search_faults.py`를 돌려 105개 모두 통과했다. #542 하네스 S0 시험과 장애 주입 하네스 S0 시험이 여기에 든다.

## 5. 구현 뒤 #542 하네스 대조 (base와 head)

- 입력: 1절과 같은 코퍼스 한 벌. 적재는 checkout마다 따로 했고 둘 다 `COMPLETE`였다(base 73.9초, head 72.6초).
- 실행: base 적재, base 기본, base 축소 상한, head 적재, head 기본, head 축소 상한을 한 transient 서비스 안에서 하나씩 돌렸다. 네 보고서 모두 `verdict: COMPLETE`, `bm25_index`는 `db`다.

| 레그 | base 기본 | head 기본 | base 축소 상한 | head 축소 상한 |
|---|---|---|---|---|
| BM25 | pass 42 | pass 42 | pass 42 | pass 42 |
| FTS | pass 42 | pass 42 | pass 42 | pass 42 |
| vector | pass 42 | pass 42 | pass 42 | pass 42 |
| 결합 | pass 40, partial_silent 1, miss 1 | pass 41, miss 1 | pass 40, partial_silent 1, miss 1 | pass 41, miss 1 |

- 질의별 대조: 두 설정 모두 레그나 결합의 분류, 누락, 정답 순위, 대조군 수가 바뀐 질의는 `top-k-pressure-1` 결합 하나다. `partial_silent`(대조군 10개 위)에서 `pass`(대조군 9개 위)가 됐다. 자동 선택 판정은 바뀌지 않았다. 결합 `miss` 하나는 base와 같은 `long-tail-1`이다.
- 반복 결함 표지: 누출, 중복, 범위 오류, 경고 누락, 동시 쓰기 누출과 중복은 네 보고서 모두 0이다. 조용한 부분 결과 표지는 base 5(결합, 다섯 반복), head 0이다.
- 요구치: base에서 미충족이던 `quality_partial_silent`가 head에서 충족됐다. `quality_combined_non_pass`는 `long-tail-1` 때문에 양쪽 모두 미충족이다.
- `compare` 출력: 두 설정 모두 `COMPARE: CLEAN`, 종료 코드 0.
- 지연: 요청 p95(명시 단일 팩, 명시 다중, 전체 범위, 자동 선택)는 기본 설정에서 base 145.0, 10.2, 21.6, 13.2ms, head 145.1, 10.5, 18.7, 13.4ms였다. 축소 상한에서 base 144.9, 13.4, 21.4, 13.2ms, head 144.0, 10.5, 18.4, 13.3ms였다. 표본 peak RSS는 146.7MiB에서 154.0MiB 사이였다.

## 6. 구현 뒤 id 대조와 `fusion:` 경고 목록

- 방법: base 기본 실행 디렉터리와 base 축소 상한 실행 디렉터리의 사본을 checkout마다 따로 만들었다. base checkout과 head checkout이 각각 같은 사본 원본에서 질의 42개의 자동 선택, BM25, FTS, vector 레그, rerank 결합, 평면 병합의 id 목록과 결합 `warnings`를 냈다. 축소 상한은 `opencrab` import 전에 행 상한을 전체 노드 수의 25%(올림, 5038)로 두었다. 각 프로세스가 자기 checkout의 `opencrab`을 import했음을 출력으로 확인했다.
- 결과(두 설정 같음): 자동 선택과 세 레그의 id 목록은 42개 모두 같다. rerank 결합이 바뀐 질의는 `top-k-pressure-1` 하나다. 정답이 창 밖에서 10위로 왔고 밀려난 결과는 대조군이다. 평면 병합이 바뀐 질의는 `auto-content-0`, `auto-content-2`, `explicit-mixed-1`(정답이 창 밖에서 10위로 옴), `auto-title-0`(정답 없는 질의, 끝 칸에 BM25 1위가 옴), `top-k-pressure-1`(정답 2위 그대로, 끝 칸에 FTS 1위인 대조군이 오고 대조군 하나가 밀림)이다. 설계 8절 표와 같다. 정답 순위가 내려간 질의는 없다.
- `fusion:` 경고: base는 두 경로 모두 0개다. head의 rerank 결합은 두 설정 모두 `top-k-pressure-2` 하나(창 밖 vector 1위)다. head의 평면 병합은 0개다. `fusion:`가 아닌 경고는 base와 head가 42개 질의 모두 같다.
