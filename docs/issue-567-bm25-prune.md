# #567 노드 BM25 DB 색인의 상위 k 가지치기

이 문서는 #567의 설계다. 살아 있는 문서이므로 관측 수치를 적지 않는다. 착수 전 probe와 base 대 head 대조의 수치는 날짜를 박은 기록(`docs/records/issue-567-bm25-prune-2026-10-26.md`)에 둔다.

## 1. 결론

`_node_bm25_sqlite.search`에 정확한 상위 k 경로를 하나 더한다. 이 경로는 MaxScore 계열(Turtle과 Flood, "Query evaluation: strategies and optimizations", IP&M 1995)의 용어 단위 가지치기다. 상한이 큰 용어부터 처리하고, 남은 용어의 점수 상한 합이 각 그룹의 k번째 하한보다 작아지면 새 문서를 더 받지 않는다. 남은 후보의 점수는 남은 용어의 출현 목록을 훑거나 후보 문서를 다시 토큰화해 정확히 계산한다. 마지막 순위와 점수는 기존 공용 함수 `bm25_score`로 다시 계산하고, 기존과 같은 동점 순서와 같은 현재 행 검사를 거친다. 그래서 결과의 항목, 점수, 순서는 기존 DB 경로와 같다. 근사는 쓰지 않는다.

색인 형식, 스키마, 쓰기 경로는 바꾸지 않는다. 라이브 적용은 코드 교체와 서비스 재시작뿐이다. 재색인은 없다(9절).

이 경로로도 요구치를 넘는 질의 형태가 남는다. 흔한 용어만 여섯 개 담은 전체 팩 질의와 흔한 용어만 담은 팩별 탐침이다. 관측한 실행에서 이 알고리즘은 그 용어들의 출현 목록을 대부분 읽은 뒤에야 후보를 줄였다(12절). 리드는 정확한 경로를 유지하고 두 형태를 잔여로 남기기로 재정했다(12절).

## 2. 근본원인 (소스와 측정 근거)

현재 `search`는 고유 질의 용어마다 아래 SQL을 한 번 실행한다.

```sql
SELECT v.doc, COUNT(*), d.dl, d.updated_at, d.space, d.node_id, d.pack_id
FROM doc_nodes_bm25_vinst v JOIN doc_nodes_bm25_docs d ON d.doc_key = v.doc
WHERE v.term = ? AND d.pack_id IN (...) GROUP BY v.doc
```

착수 전 probe(날짜 기록 2절)에서 비용은 세 곳에서 나왔다.

- 출현 하나마다 `docs` 행을 기본 키로 찾는다. 질의 계획은 `SCAN v VIRTUAL TABLE`, `SEARCH d USING INTEGER PRIMARY KEY`, `USE TEMP B-TREE FOR GROUP BY`다. 흔한 용어는 출현이 문서 수보다 많으므로 이 조인과 정렬기가 출현 수에 비례한다.
- Python이 후보 문서마다 튜플과 사전을 만들고 `bm25_score`를 부른다. 흔한 용어 위주 질의는 후보가 코퍼스 대부분이다.
- 상위 k만 돌려주면서도 일치한 모든 문서의 점수를 계산하고 정렬한다. #541 설계 4.5절의 마지막 문단은 이 비용을 알았고 가지치기를 후속으로 미뤘다. 원문은 다음과 같다. "공통 용어(거의 모든 문서에 있는 토큰)를 담은 질의는 `vinst`가 그 용어의 모든 출현을 훑는다. 비용은 코퍼스 전체의 출현 수에 비례하고 요청 팩 크기와 무관하다."

같은 probe에서 FTS5 내부 연산 자체는 싸다. `vinst`의 용어 한정 순회는 C 안에서 출현당 수십 ns 단위이고, `MATCH`의 문서 단위 순회는 그보다 싸다. 그래서 비용의 대부분은 출현 단위 조인, GROUP BY 정렬기, Python의 문서별 처리, 상위 k 밖 문서의 점수 계산이다.

## 3. 받아들임 기준 (이슈 원문)

> - 위 관측의 질의 형태가 #542 지연 요구치 안에 든다.
> - 결과 집합과 순위가 오라클과 같다. 근사이면 품질 분류가 나빠지지 않는다.
> - 합성 코퍼스에서 이 비용을 재현하는 질의가 생긴다.

리드가 정한 Outcome의 추가 조건은 다음과 같다.

- 같은 질의에서 결과 집합과 순위가 지금 DB 경로와 같다. #541 오라클 시험과 #550 점수 동일성 시험이 그대로 통과한다.
- #542 합성 코퍼스에 흔한 용어 분포와 그 비용을 재현하는 질의를 더하고, base에서는 요구치를 넘고 head에서는 요구치 안에 드는 것을 보인다.
- 라이브 규모 검증은 보호 백업의 스크래치 사본으로 한다. 관측 질의 형태가 base에서 느리고 head에서 요구치 안에 드는 것을 보인다. 질의 문자열과 팩 이름은 비공개 스크래치에만 둔다.
- 범위 밖: 결합 규칙(#556), BM25 점수식(#550), #565의 쓰기 지연, #568 REST API.

관측 질의 형태와 요구치의 대응은 다음과 같다. 질의 형태는 리드의 라이브 리허설 스크립트를 스크래치에서 그대로 재현했다(날짜 기록 1절).

| 관측 형태 | 대응 요구치(#542 4.3절) |
|---|---|
| 팩 지정, 흔한 노드 문장 6토큰 | BM25 레그 p95 500ms |
| 대형 팩 지정, 토큰 40개의 긴 질의(자연어 질의 묶음) | BM25 레그 p95 500ms |
| 자동 선택, 전체 팩 대상 팩별 탐침(자연어 질의) | 자동 선택 요청 p95 2500ms |

라이브 검증의 요청 크기는 서비스와 같게 둔다. BM25 레그의 요청 크기는 `_profile_for_query`의 `bm25_limit = min(max(limit * (multiplier + 2), 40), 180)`이다. MCP 기본 `limit` 10에서 일반 질의는 60, 관계 질의는 100이다. 그래서 레그 판정은 60과 100 두 크기로 한다. 팩별 탐침은 `PER_PACK_PROBE_LIMIT`인 50이다. 리허설은 10과 5를 썼다.

판정 범위는 다음과 같다.

- 라이브 규모 사본: BM25 레그(크기 60과 100)와 팩별 탐침은 `search` 호출 시간으로 판정한다. 자동 선택 요청은 `resolve_packs`와 `HybridQuery.query`를 사본의 문서 저장소와 SQL 저장소(같은 백업 세트의 `opencrab.db` 사본)로 부른 시간으로 잰다. KURE 임베딩 서버를 쓰지 않으므로 vector 레그와 graph 레그는 끈다. 그래서 라이브 사본의 자동 선택 요청 수치는 vector 레그 시간을 뺀 값이며, 기록에 그 사실을 적는다.
- 합성 코퍼스(#542 하네스): 자동 선택 요청 p95는 하네스가 vector 레그(해시 임베딩)까지 포함한 요청 전체로 잰다. 요구치 판정의 정본은 이 값이다.

## 6. 설계

### 6.1 진입 조건

`search`는 지금처럼 같은 읽기 스냅숏에서 `meta` 상태, pending 수, 질의 용어, stats, df를 읽는다. 아래 조건이 모두 맞을 때만 가지치기 경로로 간다. 하나라도 어긋나면 지금 경로를 그대로 탄다.

- 스위치 `OPENCRAB_BM25_PRUNE`이 `0`이 아니다.
- 스냅숏의 pending 수가 0이다. pending이 있으면 지금 경로가 pending 키를 빼고 경고를 낸다.
- `limit > 0`이다. 0과 음수는 지금 경로가 `scores[:limit]` 뜻을 지킨다.
- `len(q_terms) ≤ PRUNE_MAX_TERMS`다. 6.4절 오차 한계의 전제다.
- 계산한 모든 `idf`가 0보다 크다. `bm25_idf`는 실수 값이 늘 양수지만, 계산값은 문서 수가 아주 크면 0이 될 수 있다(검증자 실측: `bm25_idf(2**52, 2**52)`가 `0.0`). 이 조건이 있어야 6.2절의 상한이 엄격하고 6.4절의 점수와 하한이 양수다.
- 팩별 모드이거나, 질의 용어의 `cnt` 합이 모듈 상수 `FULL_SCAN_CF_MAX`보다 크다. 출현이 적은 질의는 지금 경로가 더 싸다(날짜 기록 4절). 이 상수는 결과를 바꾸지 않고 비용만 고른다.

### 6.2 정의

- `q_terms`: `tokenize(question)`을 `fts_term`으로 바꾼 목록. 순서와 중복을 지킨다.
- `T`: df가 0보다 큰 고유 용어. `mult(t)`: `q_terms` 안의 반복 수. `idf(t) = bm25_idf(N, df)`.
- 상한 `ub(t) = mult(t) * idf(t) * (K1 + 1 + δ)`. `bm25_score`에서 질의 위치 하나의 기여는 `idf * (tf(K1+1) / (tf + K1(1 - b + b*dl/max(avgdl, 1))) + δ)`이다(`bm25.py`의 원문 `denominator = tf + _K1 * (1 - _B + _B * dl / max(avgdl, 1))`). 분수는 `K1 + 1`보다 엄격히 작다. 분모의 둘째 항이 `K1(1 - b) > 0` 이상이기 때문이다. 그래서 어떤 문서에서도 `t`의 기여 합은 실수 연산에서 `ub(t)`보다 작다.
- 부분 점수의 식: 부분 점수에 더하는 용어 기여는 공용 함수와 같은 식(`max(avgdl, 1)` 포함)을 numpy로 계산한 값이다. 식이 같아도 덧셈 순서와 반복 수의 곱셈이 `bm25_score`와 다르므로 비트 단위로 같지 않다. 이 차이는 6.4절의 오차 여유가 덮는다.
- 그룹: 팩별 모드는 요청 팩 하나가 그룹 하나다. 아니면 그룹이 하나다. `k = limit`.
- 후보 `C`: 문서마다 `doc_key`, 그룹, `dl`, 부분 점수, 정확 점수(알면), 처리한 용어의 tf를 가진 배열 묶음이다.
- 하한 `L(d)`: 정확 점수를 알면 그 값, 아니면 처리한 용어의 기여 합(부분 점수). 모든 기여가 0 이상이므로 실수 값에서 최종 점수 이하다.
- 대기 용어 `P`: 아직 처리하지 않은 용어. `rest`는 `P`의 `ub` 합이다. 곱하는 팽창 계수는 없다.
- `θ(g)`: 그룹 `g` 후보의 `L` 가운데 k번째로 큰 값. 후보가 k개보다 적으면 음의 무한대다.
- 상대 여유 `ρ = 2^-30 * (len(q_terms) + 32)`. 비교하는 값은 모두 음이 아닌 항의 합이므로 반올림 오차가 그 값에 비례한다(6.4절 끝 문단의 `μ`). `ρ`는 `μ`의 여러 배다. `len(q_terms)`가 모듈 상수 `PRUNE_MAX_TERMS`(4096)를 넘으면 가지치기 경로에 들어가지 않는다(6.1절 진입 조건).
- 그룹 `g`는 `θ(g) * (1 - ρ) > rest * (1 + ρ)`인 단계에서 닫힌다. 한 번 닫힌 그룹은 끝까지 닫힌 상태로 둔다(닫힘 표지를 계산값으로 다시 판정하지 않는다).

### 6.3 단계

1. `T`를 `(-ub, term)` 순서로 정렬해 받는 순서로 둔다.
2. 단계마다 다음을 한다.
   1. 정확 점수 심기: 그룹마다 `L`이 큰 k개 가운데 정확 점수가 없는 문서를 다시 토큰화해 정확 점수를 구한다. 다시 토큰화의 예상 비용이 예산 상수를 넘으면 이 단계를 건너뛴다. 정확 점수는 하한을 올려 `θ`를 키운다.
   2. 가지치기: 상한(정확 점수를 알면 그 값, 아니면 `부분 점수 + rest`)에 `1 + ρ`를 곱한 값이 그 문서 그룹의 `θ * (1 - ρ)`보다 작은 후보를 지우고, 지운 키를 `dead`에 둔다. 이어서 닫힘 조건을 만족한 그룹에 닫힘 표지를 붙인다.
   3. 모든 그룹이 닫혔으면 새 문서를 받지 않는다. 정확 점수가 없는 후보를 다시 토큰화하는 예상 비용이 대기 용어 전체의 출현 목록을 훑는 예상 비용 이하이면 다시 토큰화로 끝낸다. 아니면 대기 용어 가운데 `ub / cnt`가 가장 큰 용어 하나의 출현 목록을 훑어 기존 후보의 tf만 채우고 2번으로 돌아간다.
   4. 열린 그룹이 있으면 받는 순서의 다음 용어 `t`를 처리한다. `MATCH`와 `docs` 조인으로 열린 그룹의 팩과 space 안에 있는 `t`의 문서를 `(doc_key, dl, 그룹)`으로 받는다. 이 가운데 `C`와 `dead`에 없는 문서가 새 문서다. 새 문서와 정확 점수가 없는 기존 후보를 다시 토큰화하는 예상 비용이 `t`의 출현 목록을 훑는 예상 비용보다 작으면 다시 토큰화한다. 아니면 출현 목록을 훑어 기존 후보와 새 문서의 tf를 채우고 부분 점수를 더한다.
3. 대기 용어가 없으면 끝낸다.
4. 최종 선택: 그룹마다 `L ≥ θ(g) * (1 - 2ρ)`인 후보를 고른다. 이 시점의 `L`은 모든 용어를 반영한다. 고른 후보마다 정확 점수가 없으면 처리한 용어의 tf로 `bm25_score`를 부른다. 점수가 0보다 큰 후보를 `docs`에서 `updated_at`, `space`, `node_id`, `pack_id`와 함께 읽어 지금 경로와 같은 `(-score, updated_at DESC, space, node_id)` 순서로 정렬한다.
5. 정렬 목록을 지금 경로의 현재 행 검사(pending, 행 존재, 현재 `scope_pack_id`, space, 팩별 모드의 같은 팩)에 그대로 넣는다. 검사가 후보를 하나라도 버리면 가지치기 경로의 결과를 버리고 지금 경로로 처음부터 다시 계산한다.

비용 추정 상수(출현당 비용, 다시 토큰화의 문서당 비용과 토큰당 비용, 심기 예산)는 모듈 상수다. 상수는 경로 선택만 바꾸고 결과는 바꾸지 않는다. 다시 토큰화 비용은 `docs.dl`로 추정한다. 긴 문서는 토큰화가 비싸기 때문이다.

### 6.4 정확성

결과가 지금 경로와 같다는 근거는 다음 다섯이다.

먼저 기호를 정한다. 실수 값은 계산값과 같은 입력(계산한 `idf`, `avgdl`, 정수 `tf`와 `dl`)으로 반올림 없이 계산한 값이다. 지금 경로와 가지치기 경로는 같은 계산값 `idf`와 `avgdl`을 쓰므로 이 정의로 충분하다. `ŝ(d)`는 `bm25_score`의 계산값(지금 경로의 순위 값), `s(d)`는 그 실수 값이다. 6.4절 끝 문단에 따라 이 경로가 비교하는 모든 계산값 `x̂`(부분 점수, 정확 점수, `ub`, `rest`, `부분 점수 + rest`, `ŝ`)는 실수 값 `x`에 대해 `|x̂ - x| ≤ μ x`다. 비교식의 곱셈 `(1 ± ρ)`도 반올림 한 번을 더할 뿐이다. `ρ ≥ 8μ`다. 6.1절의 `idf > 0` 조건 아래에서 후보는 모두 적어도 한 용어의 기여 `idf * (분수 + δ) ≥ idf * δ > 0`을 가지므로 모든 점수, 부분 점수, 하한, `ub`, `rest`(대기 용어가 있을 때)가 양수다. 그래서 상대 비교가 성립한다. 대기 용어가 없으면 `rest`는 쓰지 않는다.

1. 받지 않은 문서는 계산값 순위의 상위 k에 들 수 없다. 그룹 `g`의 문서 `d`가 `C`에도 `dead`에도 없으면, `d`의 용어를 처음 처리한 단계에서 `g`가 닫혀 있었다. 닫힌 단계에서 계산값으로 `θ(g)(1 - ρ) > rest(1 + ρ)`였다. 그 단계의 `rest`는 `d`의 모든 용어를 담으므로 `s(d) < rest_실수 ≤ rest(1 + 2μ)`다(`ub`가 엄격한 상한이다). 그 단계에서 계산 하한이 `θ(g)` 이상인 문서 k개 `j`는 `ŝ(j) ≥ s(j)(1 - μ) ≥ L_실수(j)(1 - μ) ≥ θ(g)(1 - μ)^2`다. 그래서 `ŝ(d) ≤ s(d)(1 + μ) < rest(1 + μ)(1 + 2μ) < θ(g)(1 - ρ)(1 + μ)(1 + 2μ) / (1 + ρ) ≤ θ(g)(1 - μ)^2 ≤ ŝ(j)`다(마지막 부등식은 `ρ ≥ 8μ`에서 나온다). `d`는 계산값 순위에서 k개 문서보다 엄격히 낮으므로 동점 순서와 무관하게 상위 k 밖이다. 닫힘을 고정해도 되는 이유: 실수 값의 하한은 줄지 않는다(기여를 더하거나 같은 실수 점수로 바꿀 뿐이다). 가지치기는 계산 하한이 `θ(g)` 이상인 k개 문서를 지우지 않는다(그 문서들의 상한은 하한 이상이다). 실수 값의 `rest`는 늘지 않는다. 그래서 닫힌 단계의 부등식 사슬은 그 뒤에도 성립한다. 계산값의 `θ(g)`는 반올림으로 줄 수 있으므로 닫힘을 다시 판정하지 않는다.
2. 지운 문서도 상위 k에 들 수 없다. 지울 때 계산값으로 `상한(1 + ρ) < θ(g)(1 - ρ)`였고, 상한의 실수 값은 `s(d)` 이상이다. 1번과 같은 부등식 사슬로 그 문서는 계산값 순위에서 k개 문서보다 엄격히 낮다. `dead`의 키는 다시 받지 않는다. 다시 받으면 앞서 처리한 용어의 tf가 빠진 점수로 계산되기 때문이다.
3. 최종 선택은 계산값 순위의 상위 k와 경계의 동점을 모두 담는다. 끝난 뒤 모든 후보의 `L`은 모든 용어를 반영한 계산값이다. `θ(g)`를 만든 k개 문서는 `ŝ ≥ θ(g)(1 - μ)^2 / (1 + μ)`다. 그래서 그룹의 계산값 순위에서 k번째 값 `ŝ_k`도 그 이상이다. `ŝ(d) ≥ ŝ_k`인 모든 후보 `d`는 `L(d) ≥ ŝ(d)(1 - μ)/(1 + μ) ≥ θ(g)(1 - μ)^3/(1 + μ)^2 ≥ θ(g)(1 - 2ρ)`이므로 최종 선택에 든다. 1번과 2번에 따라 `C` 밖의 문서는 `ŝ_k`보다 엄격히 낮다. 최종 순서는 고른 문서의 `ŝ`와 지금 경로의 동점 키로 정하므로 지금 경로의 앞 k개와 같다.
4. 점수와 순서가 같다. 최종 점수는 지금 경로와 같은 `bm25_score(q_terms, tf_map, idf, dl, avgdl)`로 계산한다. tf는 지금 경로와 같은 `vinst` 출현 목록에서 오거나, 다시 토큰화에서 온다. 정렬 키와 현재 행 검사는 지금 경로와 같다.
5. 다시 토큰화는 색인과 같은 용어 열을 낸다. `reindex_key`와 같은 `node_terms(row_to_node(row), meta의 max_text_chars)`를 쓴다. pending이 0인 스냅숏에서 색인 항목은 현재 행과 같은 시점이다. 이 전제를 검사로 확인한다(6.5절).

부동소수 상대 오차 한계 `μ`: `u = 2^-53`, `n = len(q_terms)`라 하자. `bm25.py`의 `bm25_score`는 질의 위치 하나의 기여를 `numerator = tf * (_K1 + 1)`, `denominator = tf + _K1 * (1 - _B + _B * dl / max(avgdl, 1))`, `score += term_idf * (numerator / denominator + _DELTA)`로 계산한다. 상수끼리의 연산(`_K1 + 1`, `1 - _B`)을 빼면 반올림하는 연산은 9번이다. 모든 피연산자가 양수이므로 기여 하나의 상대 오차는 `γ_9 = 9u / (1 - 9u)` 이하다. 음이 아닌 값 `m`개의 순차 합은 상대 오차가 `γ_(m-1)` 이하다(Higham, Accuracy and Stability of Numerical Algorithms, 2판, 4.2절). 그래서 `ŝ`는 실수 값에 대해 상대 오차 `γ_(n+8)` 이내다. numpy 부분 점수는 용어마다 같은 식에 반복 수를 곱한 기여(반올림 10번 이내)를 용어 수 `|T| ≤ n`개만큼 더하므로 `γ_(n+10)` 이내다. `ub`는 반올림 2번, `rest`는 `ub` 최대 `n`개의 합이므로 `γ_(n+2)` 이내다. `부분 점수 + rest`는 반올림이 1번 더해진다. 그래서 `μ = γ_(n+16)`이 모든 비교값을 덮는다. `n ≤ 4096`이면 `μ < 1.01 (n+16) u < 4.7 × 10^-13`이고 `n ≥ 1`이므로 `ρ = 2^-30 (n+32) ≥ 33 × 2^-30 ≈ 3.07 × 10^-8`이고, 그래서 `ρ`는 `μ`의 `2^20`배 이상이다. 여유가 크면 가지치기만 약해지고 결과는 바뀌지 않는다. 절대 여유(모든 `ub`의 합에 비례) 대신 상대 여유를 쓰는 이유는 점수가 아주 작은 그룹(거의 모든 문서에 있는 용어만 담은 팩)에서 절대 여유가 그룹의 모든 후보를 최종 선택에 남기기 때문이다(날짜 기록 6절). 시험은 같은 용어를 1000번 반복한 질의와 `avgdl < 1` 코퍼스를 고정 사례로 둔다.

### 6.5 불일치 감지와 지금 경로로의 복귀

아래 검사 가운데 하나라도 어긋나면 `PruneFallbackError` 예외로 가지치기 경로를 버리고, 같은 스냅숏에서 지금 경로로 계산한다. 경고는 남기지 않는다. 결과가 지금 경로와 같기 때문이다. 로그는 `logger.warning`으로 사유를 남긴다.

- `MATCH '"<용어>"'`의 행 수가 `vrow`의 df와 다르다. 질의 문법이나 토크나이저 해석이 출현 목록과 다르다는 뜻이다.
- `MATCH` 조인이 준 새 문서가 그 용어의 출현 목록에 없다.
- 다시 토큰화한 용어 수가 `docs.dl`과 다르거나, 이미 훑은 용어의 tf가 출현 목록의 tf와 다르거나, 현재 행이 없다.
- `group_concat` 결과의 항목 수가 행 수와 다르다(팩 이름에 구분 문자가 든 경우를 포함한다).
- 현재 행 검사가 후보를 버린다.

### 6.6 자원 위치와 수명

- 모든 읽기는 호출자(`LocalSQLDocStore.node_bm25_search`)가 연 읽기 트랜잭션 하나 안에서 한다. 지금 경로와 같은 스냅숏이다. 복귀도 같은 트랜잭션에서 한다.
- 후보 상태는 함수 지역의 numpy 배열이다. 출현 목록은 `group_concat` 문자열로 받아 배열로 바꾼 뒤 버린다. 함수가 끝나면 모두 해제된다. 영속 상태, 캐시, 스레드가 없다.
- 쓰기가 없다. 그래서 중단 뒤 재개할 상태가 없다. 예외나 시간 상한으로 끊긴 질의는 다시 실행하면 처음부터 같은 계산을 한다.

### 6.7 되돌리기 스위치

환경 변수 `OPENCRAB_BM25_PRUNE=0`은 가지치기 경로만 끄고 지금 DB 경로를 쓴다. 질의마다 읽는다. `OPENCRAB_BM25_DB_INDEX=0`(메모리 창 경로)과 달리 누락이 다시 생기지 않는다. 이 스위치는 운영 되돌리기 수단이며 결과를 바꾸지 않는다.

## 7. 호출자와 형제 경로

- 진입점은 `_node_bm25_sqlite.search` 하나다. `LocalSQLDocStore.node_bm25_search`, `HybridQuery._node_index_search`를 거쳐 `_bm25_search_state`, `_bm25_search_per_pack`(자동 선택 탐침), `_bm25_search_with_warnings`, `_bm25_search`가 모두 이 함수를 부른다. 한 곳을 고치면 모든 BM25 레그와 팩별 탐침이 함께 바뀐다.
- 메모리 경로(`BM25Index.search`, PG, MongoDB, 킬 스위치, `backfill`)는 바꾸지 않는다.
- 결합(#556), rerank, 접기, 정책 필터, `pack_registry._accumulate`는 결과 항목의 모양만 읽는다. 항목이 같으므로 바뀌지 않는다.
- `verify`, `backfill_step`, `drain`, `reindex_key`는 바꾸지 않는다.

## 8. SOLID 판정

- 단일 책임: 가지치기 알고리즘은 새 모듈 `opencrab/stores/_node_bm25_prune.py`에 둔다. 호출자는 `_node_bm25_sqlite.search` 하나다. `search`는 진입 조건, 복귀, 현재 행 검사를 맡는다. 현재 행 검사는 지금 경로와 가지치기 경로가 함께 쓰므로 `search` 안의 기존 함수를 그대로 쓴다.
- 개방 폐쇄: 분기는 진입 조건 하나다. 새 분기를 위한 등록표는 만들지 않는다.
- 리스코프 치환: 가지치기 경로의 반환값(항목의 키와 값, 순서, 경고)은 지금 경로와 같다. 오라클 시험이 이를 고정한다.
- 인터페이스 분리: 새 모듈의 진입 함수는 연결, `row_to_node`, 질의 용어, idf와 통계, 팩, space, limit, 팩별 여부만 받는다.
- 의존 역전: 구현이 하나뿐이므로 인터페이스 타입을 만들지 않는다.

## 9. 색인 형식, 쓰기 비용, 라이브 적용

- 형식 버전(`meta.format`)을 올리지 않는다. 스키마, 트리거, `reindex_key`, stats 갱신을 바꾸지 않는다. 그래서 쓰기 비용(#565)이 늘지 않는다.
- 라이브 적용: 리드와 사용자 승인, 기존 백업 도구로 백업 세트 생성과 검증, 새 코드로 두 `serve` 인스턴스 재시작, 알려진 질의로 결과와 지연 확인. 재색인과 backfill은 없다.
- 되돌리기: `OPENCRAB_BM25_PRUNE=0`으로 재시작하거나 옛 코드로 재시작한다. DB를 바꾸지 않으므로 DB 되돌리기는 없다.
- 형식이 섞인 상태: 생기지 않는다. 옛 코드와 새 코드가 같은 파일을 함께 열어도 같은 결과를 낸다.

## 10. 시험 전략

새 시험은 `tests/test_node_bm25_prune.py`에 둔다. 모두 `tmp_path`의 실제 `LocalSQLDocStore`를 쓴다. 작은 코퍼스는 6.1절의 비용 조건 때문에 지금 경로를 타므로, 시험은 `FULL_SCAN_CF_MAX`를 0으로 낮춰 가지치기 경로를 강제한다.

- 오라클 동등성: #541 오라클 시험의 코퍼스 생성 규칙(여러 팩, 두 space, 한국어와 영어, 같은 본문 다른 ID, 긴 본문, 깨진 properties, 숫자 `pack_id`, 무소속 행)에 Zipf 빈도의 흔한 용어와 드문 용어를 더한다. 질의, 팩 집합, `spaces`, `limit`(1, 3, 10, 40)의 조합마다 가지치기 경로의 결과가 `OPENCRAB_BM25_PRUNE=0`의 지금 경로 결과, 그리고 `BM25Index.build(전량).search` 결과와 항목, 점수, 순서까지 같다. 팩별 모드도 같다.
- 가지치기 작동: 드문 용어를 담은 문서가 k개보다 많고 흔한 용어가 섞인 질의에서 출현 목록을 훑은 용어 수가 질의 용어 수보다 적다. 결과는 지금 경로와 같다. 출현 목록 함수를 감싸 호출 수를 센다.
- 다시 토큰화 경로: 비용 상수를 조정해 열린 단계의 다시 토큰화와 닫힌 단계의 다시 토큰화를 각각 강제한다. 결과가 지금 경로와 같다.
- 동점 경계: 같은 본문 여러 개가 k번째 자리에 걸치는 코퍼스에서 순서가 지금 경로와 같다(`updated_at`, `space`, `node_id`).
- 복귀: pending이 있는 스냅숏, `limit` 0과 음수, 스위치 `0`은 지금 경로를 탄다. `MATCH` 행 수 불일치, 다시 토큰화 길이 불일치, 현재 행 검사의 버림을 주입하면 지금 경로의 결과와 같다.
- 점수식 경계: `avgdl < 1`인 코퍼스(빈 본문이 많아 평균 길이가 1보다 작음)에서 `(tf, dl)`이 서로 다른 두 문서의 순위가 지금 경로와 같다. 검증자 반례(문서 225개, 총 길이 45, `(1, 4)`와 `(10, 41)`)를 고정 사례로 넣는다.
- 긴 반복 질의: 같은 용어를 1000번 반복한 질의와 여러 용어를 섞은 긴 질의에서 결과가 지금 경로와 같다.
- 복귀 관측: 동등성 시험마다 가지치기 경로가 복귀 없이 끝났는지 확인한다. 복귀해서 통과하는 경우를 구별하기 위해서다. 가지치기 작동 시험은 출현 목록 호출 수와 다시 토큰화 문서 수를 따로 세어, 다시 토큰화 없이 출현 목록만 줄어든 경우를 하나 둔다.
- 기존 시험: `tests/test_node_bm25_index.py`(#541 오라클)와 `tests/test_bm25_lower_bound.py`(#550)를 바꾸지 않고 통과시킨다. 두 파일은 작은 코퍼스라 6.1절의 비용 조건으로 지금 경로를 탄다. 그래서 같은 오라클 비교를 가지치기 경로로 강제해 새 파일에서 다시 돌린다.
- 역변이: `ub`의 `δ` 항을 빼거나 `dead` 재수용 방지를 지우면 오라클 시험이 실패한다. `rest` 비교를 끄면 가지치기 작동 시험이 실패한다(gate-recipes 6절 역변이 소절의 수동 절차).
- 전체 스위트를 base와 head에서 순차로 돌려 대사한다(gate-recipes 4절 상한 판과 6절).

## 11. 합성 코퍼스 질의 (#542 하네스)

생성기 `scripts/search_corpus.py`에 질의 종류 둘을 더한다. 둘 다 기존 질의 계획이 끝난 뒤(남은 긴 본문 선택 뒤)에 계획해 기존 질의의 정답, 대조군, 본문을 바꾸지 않는다. 흔한 단어는 일반 어휘의 Zipf 상위 순위에서 고르되, 어느 팩의 제목과 설명에도 없는 단어만 쓴다. 그래야 자동 선택 질의가 manifest 점수로 끝나지 않고 콘텐츠 탐침을 탄다.

| 종류 | 질의 | 형태 | 정답 |
|---|---|---|---|
| `common-heavy` | 표지 토큰 하나와 흔한 단어 여섯 | k=0 명시 단일 대형 팩, k=1 전체 범위, k=2 자동 선택(소형 팩) | 표지 토큰 문서(기존 `exact-recent`, `whole-scope`, `auto-content`와 같은 금지 집합 규칙) |
| `common-only` | 흔한 단어만(셋 또는 여섯) | k=0 명시 단일 대형 팩 셋, k=1 전체 범위 셋, k=2 전체 범위 여섯 | 없음(누출, 중복, 지연만 판정) |

판정 함수, 요구치 키, 기존 질의는 바꾸지 않는다. `docs/issue-542-search-baseline.md` 6.1절의 종류 표에 두 행을 더한다.

생성기의 기존 검사와의 충돌은 다음과 같이 푼다. 지금 `generate`는 `auto-title`이 아닌 질의의 토큰이 일반 어휘에 있으면 `marker collides with vocabulary`로 멈춘다. 새 질의 항목에 `common_words`(흔한 단어 목록) 키를 더한다. 검사는 `common_words`를 뺀 토큰에만 기존 규칙을 적용하고, `common_words`의 단어는 일반 어휘에 있고 어느 팩의 제목과 설명에도 없음을 따로 확인한다. 기존 질의에는 이 키가 없으므로 기존 검사가 그대로 걸린다. `tests/test_search_baseline.py`의 표지 보유 검사는 질의 문자열 전체를 단어로 찾는다. 새 질의에서는 표지 토큰(`common_words`를 뺀 토큰)으로 찾게 하고, `common-only`는 정답과 금지 집합이 비어 있으므로 건너뛴다. 기존 질의의 검사는 바꾸지 않는다.

대조는 `compare`만으로 끝내지 않는다. `compare`는 base와 head가 모두 요구치를 넘으면 회귀로 보고하지 않는다. 그래서 대조 보고에 base의 BM25 레그 p95 초과와 head의 충족을 보고서 `requirements`에서 직접 읽어 적는다.

대조 계획: 새 생성기로 S2 코퍼스를 만들고, base(`origin/main`)와 head의 하네스로 같은 적재 디렉터리의 사본을 순차로 돌려 `compare`한다. 기대는 다음과 같다.

- base의 BM25 레그 p95가 500ms를 넘는다. 새 질의의 표본이 p95 자리를 차지하기 때문이다.
- head의 BM25 레그 p95와 자동 선택 요청 p95가 요구치 안에 든다.
- 기존 질의의 분류는 base와 같다. 새 질의는 누출, 중복, 범위 오류, 경고 누락, 조용한 부분 결과가 0이다.

## 12. 남는 질의 형태와 기준 1의 해석 (리드 재정, 2026-10-26)

착수 전 시제품(날짜 기록 4절과 5절)에서 아래 두 형태는 정확한 경로로도 요구치를 넘었다. 결과는 지금 경로와 같았다. 시도한 방법은 출현 목록을 후보 문서로 제한하는 조건(전체 순회보다 느림), 정확 점수 심기, 닫힌 단계의 용어 순서 최적화, 다시 토큰화 마무리다.

- 흔한 용어 6개, 전체 팩, BM25 레그: 요구치 500ms를 넘었다. 단계 기록(날짜 기록 5절)에서 첫 용어를 받은 직후 그룹이 닫혔다. 그러나 후보가 그 용어의 문서 대부분으로 남았고, 닫힌 단계에서 출현 목록을 세 번 더 훑은 뒤에야 후보가 수백 개로 줄었다. 같은 실행에서 출현 목록 시간의 합(첫 용어 포함 네 번)은 전체의 절반을 넘었다. 출현 목록을 후보로 제한하는 조건은 이 데이터에서 전체 순회보다 느렸다(날짜 기록 3절). 다른 용어 순서와 다른 알고리즘은 재지 않았으므로, 이 서술은 관측한 알고리즘과 실행에 한정한다.
- 흔한 용어 3개, 전체 팩 대상 팩별 탐침: BM25 탐침만으로 1초를 넘었다. 단계 기록에서 첫 용어를 받은 뒤 닫힌 팩은 요청 팩의 일부였다. 나머지 팩은 남은 두 용어(모든 문서에 있음)로 문서를 받아야 해서 후보가 전체 문서의 대부분이 되었다. 팩별 모드에서 정확 점수 심기를 끄면 자연어 팩별 탐침이 빨라졌다(날짜 기록 5절). 그래서 심기는 다시 토큰화 예상 비용이 예산 안일 때만 한다. 이 형태는 이슈 본문의 자동 선택 관측 범위(자연어 질의)에는 없고 리허설 스크립트에만 있다.

선택지는 셋이었다. 가는 정확한 경로를 유지하고 두 형태를 잔여로 기록하는 안이다. 나는 두 형태에만 근사를 더하는 안이다(오라클과 결과가 달라진다). 다는 색인 형식을 바꾸는 안이다(라이브 재색인과 쓰기 비용 측정이 필요하다).

리드가 가를 채택했다. 결정 주체는 리드이고, 권한 근거는 리드가 #567의 받아들임 기준을 썼다는 사실과 사용자 상시 지시 "네가 결정할건 결정해서 멈추지 않도록 할것"이다. 리드가 든 근거는 다음과 같다. 정확성은 #541과 #550 오라클이 고정한 계약이므로 근사는 정당화 비용이 크다. 형식 변경은 라이브 재색인과 #565 쓰기 비용 측정을 다시 요구한다. 잔여 1은 출현 순회 비용의 하한에 닿은 극단 형태다. 잔여 2는 이슈 본문의 관측 범위(자연어 자동 선택) 밖이다.

기준 1은 다음과 같이 해석한다. "이슈 본문의 관측 형태는 요구치 안에 든다. 흔한 용어만으로 된 극단 형태 두 개는 정확한 경로의 하한에 닿아 잔여로 남는다." 잔여 두 형태는 리드가 새 이슈로 등록한다. 합성 코퍼스의 재현 질의(11절)는 잔여 형태와 같은 꼴(흔한 단어만 여섯, 전체 범위)을 담고, 대조 보고에서 잔여로 표시한다.
