# MCP 클라이언트 인증 호환성

localcrab 의 MCP HTTP 엔드포인트에 **어떤 클라이언트가 어떤 방식으로 인증할 수 있는지** 를 기록한다.

이 문서가 존재하는 이유는 구체적이다. 2026-08-10, 인증 체계를 개편하면서 쿼리 파라미터 인증(`?token=`)을 "액세스 로그에 자격증명이 남는다" 는 일반론만으로 삭제하려 했다. 실제로는 **그 방식으로만 붙을 수 있는 클라이언트가 운영 중**이었다. 저장소 어디에도 클라이언트별 지원 여부가 없었기 때문에, 무엇이 끊기는지 모른 채 결정이 내려질 뻔했다.

> **인증 메커니즘을 제거하거나 기본값을 바꾸기 전에, 이 표에서 그것을 쓰는 클라이언트가 없는지 먼저 확인한다.**

## 지원 매트릭스

| 클라이언트 | `Authorization: Bearer` | URL 쿼리 파라미터 | 비고 |
|---|---|---|---|
| **claude.ai 웹** | **불가** | **가능** | 커스텀 헤더를 설정할 수 없다. 쿼리 파라미터가 **유일한** 수단이다 |
| Claude Code | 가능 | 가능 | 헤더 권장 |
| Claude Desktop | 가능 | 가능 | 헤더 권장 |
| Cursor 등 MCP 클라이언트 | 가능 | 가능 | 헤더 권장 |
| ChatGPT 커넥터 | 가능 | 가능 | 헤더 권장 |
| 인증 프록시 경유 | 프록시가 주입 | 불필요 | 백엔드는 헤더만 보면 된다 |

stdio 전송(`opencrab serve`)에는 해당하지 않는다. 자격증명이 아니라 **OS 프로세스 경계**가 신뢰의 근거이고, 서버는 로컬 사용자로 동작한다.

## 규칙

1. **헤더를 쓸 수 있으면 헤더를 쓴다.** 쿼리 파라미터는 헤더가 불가능한 클라이언트를 위한 예외다.
2. **쿼리 파라미터 인증은 기본적으로 꺼져 있다.** 필요한 배포에서만 명시적으로 켠다. 켜지 않은 배포는 아래 위험을 지지 않는다.
3. **켜면 자격증명이 평문으로 남는다** — 액세스 로그, 리버스 프록시 로그, 브라우저 히스토리, 그리고 그 URL 에서 파생되는 `Referer` 헤더. 로그 보존 정책과 토큰 회전 주기를 그에 맞춰 정한다.
4. **Origin 검증은 인증과 별개의 앞단 계층이다(#136).** Origin 헤더가 없는 요청(위 표의 모든 클라이언트)은 영향이 없고, 브라우저가 보내는 Origin 은 loopback 이거나 `MCP_ALLOWED_ORIGINS` 에 등록되어야 한다(아니면 토큰이 유효해도 403). 상세는 [mcp-protocol-compat.md](./mcp-protocol-compat.md).
5. **쿼리 파라미터 경로도 헤더 경로와 동일한 검증을 받는다.** 미존재·폐기된 토큰과 비활성 사용자의 토큰은 어느 쪽으로 와도 거부된다. 별도의 인증 경로가 아니라 자격증명 **출처**만 다르다.

## 헤더를 못 보내는 클라이언트를 붙일 때

1. 그 클라이언트 전용 사용자와 토큰을 발급한다. **공유하지 않는다** — 노출 시 그 토큰만 폐기하면 되도록.
2. 쿼리 파라미터 인증을 켠 채로 서버를 기동한다.
3. 클라이언트 설정의 URL 에 토큰을 싣는다.
4. 토큰을 헤더 클라이언트보다 **더 자주 회전**한다. 로그에 남아 있다고 가정한다.

## 이 문서를 갱신해야 하는 때

- 클라이언트가 헤더 지원을 추가하거나 제거했을 때
- 새 인증 메커니즘(OAuth 등)을 추가했을 때
- 기존 메커니즘의 기본값을 바꾸거나 제거를 검토할 때 — **검토 시작 시점에** 이 표를 먼저 읽는다

각 행은 실제 연결 시도로 확인한 사실이어야 한다. 추측이나 외부 이슈 트래커의 서술을 근거로 적지 않는다. 2026-08-10 의 오류가 정확히 그것이었다.
