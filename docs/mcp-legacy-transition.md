# MCP legacy 경로 이행 계획 (#136 D절, 추적 이슈 #251)

`docs/mcp-protocol-compat.md` 가 **지금 무엇을 서빙하는가**를 기록한다면, 이 문서는 **legacy 세대를 언제 어떻게 끝낼 수 있는가**를 기록한다. #136(PR #243)이 dual-era 서버를 만들면서 D절(구규격 동작의 제거)을 의도적으로 범위 밖으로 남겼고, 이행 레버로 `MCP_PROTOCOL_VERSIONS` 만 마련했다. 여기서 그 잔여를 추적한다.

**현재 상태: legacy 세대는 활성이며 제거 일정이 없다.** 아래 조건표의 미지수가 채워지기 전에는 제거를 결정하지 않는다.

## 1. legacy 표면 (제거 대상의 전량)

| 표면 | 내용 |
|---|---|
| `initialize` / `notifications/initialized` | handshake 로 세션 의미를 협상. 지원 legacy 버전은 echo, 부재는 `2024-11-05` fallback, 미지·modern 전용 버전은 최신 legacy 제시 |
| `ping` | modern 에서 제거된 메서드 |
| `_meta` 없는 `tools/list` / `tools/call` | era 판정이 요청 바디의 `_meta` 부재로 legacy 로 떨어지는 모든 호출 |
| JSON-RPC 배치 배열 | legacy 전용 LocalCrab 확장 (2026-07-28 은 POST 당 요청 1건) |

## 2. 소비자 compatibility matrix

각 행의 "근거"는 이 저장소에서 확인할 수 있는 것만 적는다. 저장소 밖 소비자는 코드 조사로 이행 가능성을 판정할 수 없으므로 **미관측**으로 표기하고, 추측으로 채우지 않는다.

| 소비자 | 쓰는 legacy 표면 | 근거 | modern 이행 가능성 | 이행 주체 |
|---|---|---|---|---|
| claude.ai 커넥터 | `initialize` handshake + 쿼리 토큰 | **저장소 밖 · 미관측** (`docs/mcp-protocol-compat.md` 의 매트릭스에 기록된 관측 사실이며 소스는 이 저장소에 없다) | 불명 — 커넥터 구현이 2026-07-28 을 말하게 되어야 한다 | 소비자 측 |
| Claude Code / Claude Desktop / Cursor | `initialize` handshake, 일부 legacy `MCP-Protocol-Version` 헤더 동반 | **저장소 밖 · 미관측** | 불명 — 각 호스트의 MCP 클라이언트 구현에 달렸다 | 소비자 측 |
| OpenClaw 호스트 (agent-plugin 번들) | `initialize` echo | `docs/agent-plugin-compatibility.md` 의 호스트별 표 (**그 표가 정본이며 여기서 복제하지 않는다**) | 호스트가 2026-07-28 협상으로 전환해야 한다 | 소비자 측 |
| 대화 reingest hook (`lc_call`) | `_meta`·MCP 헤더 없는 legacy `tools/call` 은 확실. **`initialize` handshake 동반 여부는 미확정** | **저장소 밖 · 미관측이며 저장소의 두 기존 기록이 상충한다**: `docs/mcp-protocol-compat.md` 의 매트릭스는 "initialize 없이" 라 적고, `docs/ingestion-via-mcp-plan.md` 는 같은 `lc_call` 이 `initialize`→`tools/call` handshake 를 구현한다고 적는다. hook 소스가 이 저장소에 없어 어느 쪽이 맞는지 판정할 수 없다 | 가능하지만 **작업량이 미확정** — `_meta` 와 표준 헤더 추가로 끝나는지, handshake 제거까지 필요한지가 위 상충에 달렸다 | 운영자 |
| 로더 계획의 JSON-RPC 배치 | 배치 배열 | `docs/ingestion-via-mcp-plan.md` (계획 단계, 구현 코드 없음) | 설계 시점에 정하면 되므로 제약이 아니다 | 개발 |
| **저장소 소유 CI 참조 클라이언트** | `initialize` → `tools/list` → `tools/call`, `_meta` 없음 | `packaging/agent-plugin/tools/refclient.py` — 이 저장소에서 **legacy 형상 요청을 실제로 조립해 보내는 유일한 코드**. 런타임 wheel 에 포함되지 않는 저작·검증 도구다 | **가능 — 저장소가 스스로 고칠 수 있다** | 개발 (C1) |
| 계약 테스트 | 전 표면 | `tests/` — legacy 계약을 의도적으로 고정하는 파일과, 다른 관심사를 검사하며 legacy 형상을 편의로 재사용하는 파일이 섞여 있다 | 제거 시 함께 정리한다 | 개발 |

위 상충은 **C2 가 사용자에게 물어야 할 항목**이다(§4). 어느 기록이 맞는지는 hook 소스를 가진 쪽만 답할 수 있고, 근거 없이 한쪽을 지우면 정보가 준다 — 그래서 기존 두 문서를 고치지 않고 상충 사실만 여기에 기록한다.

이 표에 없는 내부 호출자는 없다. `apps/api` 는 같은 `mcp_router()` 를 마운트하는 서버 측이고, `scripts/` 와 `apps/web` 에는 MCP JSON-RPC 호출자가 없다.

### 재현 (표를 다시 확인하는 방법)

```bash
# 저장소 안에서 JSON-RPC 요청을 조립해 보내는 코드 (서버 측 응답 조립과 구분된다)
grep -rn '"jsonrpc".*"method"' --include='*.py' opencrab apps scripts packaging
# initialize / ping 표면을 쓰는 테스트 파일
grep -rln '"method": "initialize"\|"method": "ping"' tests/
```

## 3. 남은 era 간 divergence (제거 전까지 유지되는 것)

형상 검증은 #251 에서 modern 공유 검증기(`opencrab/mcp/protocol.py` 의 `validate_tools_call_params`)와 정합시켰다. legacy `tools/call` 도 비문자열 `name`, truthy 비객체 `arguments`, 비객체 `params` 를 dispatch 이전에 -32602 로 거부한다. **정합에서 의도적으로 제외한 것**은 다음 둘이며, D절 제거 시점에 함께 정리한다.

| divergence | 왜 남겼는가 |
|---|---|
| `tools/call` 의 present + **falsy 비객체** `arguments`(`null`/`[]`/`0`/`0.0`/`false`/`""`)를 `{}` 로 정규화해 도구를 실행 | **오늘 도구가 실제로 실행되는 입력**이다. 선택적 필드를 JSON null 로 직렬화하는 클라이언트가 낼 수 있는 형상이고 현재 성공하므로, 거부하면 동작하던 호출이 깨진다. 정합의 안전 규칙("도구를 실행시키던 입력은 하나도 바꾸지 않는다")이 여기서 멈추게 한다 |
| `tools/list` 의 `cursor` 무시 (modern 은 -32602) | #251 이 지목한 name/arguments 축이 아니다 |

응답 봉투 자체(modern 필드 없음, `isError` 없음)는 #136 이 바이트 호환으로 고정했고 그대로다.

### 재현

```bash
.venv/bin/pytest tests/test_mcp_legacy_call_shape.py tests/test_mcp_protocol_2026.py -q
```

## 4. 제거를 승인할 수 있는 조건

기간이 아니라 **조건**으로 정의한다. 기간을 숫자로 만들려면 이 저장소가 갖고 있지 않은 입력이 필요하다(§5).

| # | 조건 | 판정 주체 | 저장소에서 검증 가능? |
|---|---|---|---|
| C1 | 저장소 소유 CI 참조 클라이언트가 modern 형상으로 왕복한다 | 개발 | **예** — modern-only 구성에서 `server/discover` 와 `_meta` 기반 호출을 왕복시키는 스모크로 고정 가능 |
| C2 | 매트릭스의 저장소 밖 소비자 각각에 "이행 완료" 또는 "포기(깨져도 됨)" 결정이 기록돼 있다 | 사용자 | 아니오 |
| C3 | (관측을 채택하면) 연속 가동 구간에서 legacy 계수가 0 이고 그 구간이 관측창 W 이상이다 | 사용자 | 아니오 |
| C4 | modern-only 카나리를 기간 C 동안 운영해 정의된 성공 신호를 만족했다 | 사용자 | 아니오 — **오늘은 판정 불가**(§6) |

**적용되는 조건 집합은 채택한 경로가 정한다**(§5): 안 A 는 C1~C4 전부, 안 B 는 C1·C2·C4(C3 생략, C4 는 §6 (iii) 의 약한 조건으로 낮아진다).

## 5. 오늘 관측 수단이 없다

era 는 요청마다 판정되지만 **어디에도 기록되지 않는다** — 요청별 era 로그도, 카운터도, 메트릭도 없다. 리버스 프록시 로그에는 바디가 남지 않아 era 를 사후 복원할 수도 없다. 따라서 "아무도 legacy 를 안 쓴다"를 오늘 데이터로 말할 수 없다.

저장소에 버전 릴리스 태그도 없으므로("N개 릴리스 뒤"로 환산할 앵커 없음) 기간은 달력 시간과 관측 조건으로만 정의된다.

**미지수 (사용자만 답할 수 있다)**:

- **N (공지 기간)** — 저장소 밖 소비자에게 통지할 경로와 리드타임이 정해져 있지 않다.
- **W (관측창)** — 소비자별 최장 무호출 간격을 저장소에서 구할 수 없다. 커넥터와 편집기 세션은 사용자 주도라 수 주간 무호출일 수 있다.
- **C (카나리 기간)** — 롤백이 재기동뿐이라는 사실은 **위험의 상한**을 낮출 뿐 기간의 하한을 정하지 않는다. C 는 이상을 며칠 만에 알아채는가(모니터링 주기)와 얼마나 오래 깨져 있어도 되는가(롤백 SLO)에서 도출되며, 최소한 모니터링 주기보다 길어야 한다.

**두 갈래**:

- **안 A (telemetry 선행)** — era 계수를 추가하고 W 만큼 관측해 0 을 확인한 뒤 카나리 C 를 거쳐 제거한다. 제거 근거가 데이터가 된다. 비용은 계측 추가와 재기동이다.
- **안 B (관측 없이 스케줄 컷오버)** — C1 과 C2 를 만족시킨 뒤 공지하고 N 만큼 기다렸다가 modern-only 로 전환한다(C3 생략). 코드 추가가 없는 대신, C2 에서 **"포기"로 분류된** 소비자와 **매트릭스에 없으면서 legacy 표면을 계속 쓰는** 소비자가 컷오버일에 깨진다. 관측이 없으므로 후자의 존재 여부는 알 수 없다.

**계측 도입 여부가 기간 확정보다 먼저 결정되어야 한다** — C4 의 판정 가능성 자체가 거기 걸려 있다.

## 6. C4 는 오늘 판정할 수 없다

아래는 **오늘 코드에서 확인한** 거부 지점이다. 서로 배타적이며(한 요청이 두 곳에서 세어지지 않는다) 여러 지점이 `handle_request` 에 도달하기 전이다 — 각각의 조건은 게이트 칸이 밝힌다. **발동 조건은 지점마다 다르다** — 전부 modern-only 전용인 것이 아니다.

**이 목록이 전량이라고 단언하지 않는다.** 코드가 바뀌면 지점도 바뀌고, 이 문서를 검증하는 과정에서만도 두 번 새 지점이 나왔다. 계측 설계는 이 표를 그대로 믿지 말고 **재도출해야 한다**:

1. **HTTP**: `http_app.py` 의 POST 핸들러에서 **인증 통과 이후**, 요청이 종결되는 **모든 경로**를 경로별(배치 루프와 단일 요청)로 조사한다. **반환만이 아니다** — 무응답, 202 종결(배치 루프 **뒤**에 있다), 예외 종료까지 포함한다. 인증·Origin 미들웨어 단계의 거부(401·403)는 **의도적으로 집합 밖**이다: era 와 무관한 보안 게이트라 legacy 소비자를 가려내지 못한다.
2. **stdio**: `server.py` 의 `_handle_raw` **진입부터** `handle_request` 까지를 같은 기준으로 조사한다. 파싱 거부가 `handle_request` 바깥에 있어 `handle_request` 만 보면 놓친다.
3. **공용**: `handle_request` 안에서 era 분기보다 앞서 종결되는 경로.
4. **분류**: 위에서 나온 경로 중 **주 계수 지점(era 판정 직후)에 도달하지 못한 채 종결되는 것**이 계측 후보다. era 가 확정된 뒤의 거부(legacy-disabled 게이트, modern 알림의 바디 검증 거부 등)는 주 계수에 이미 잡히므로 후보가 아니다.

표는 그 집합의 **오늘 시점 스냅샷**이자 판정이 어려운 사례의 목록이다.

| # | 지점 | 게이트 | 발동 구성 |
|---|---|---|---|
| 1 | `handle_request` 의 **일반 요청(`id` 있음)** 에 대한 **`method` 부재·비문자열 거부** — era 분기보다 먼저 -32600 | 활성 버전 구성을 **조회하지 않는다** | **전 구성**. status 만 다르다(dual·legacy-only 200, modern-only 400). **알림 변형은 거부가 아니라 무응답(`None`)** 이며, modern-only HTTP 에서는 modern 신호(헤더·`_meta`)가 없으면 4번이, 있으면 6번이 먼저 잡는다 |
| 2 | `handle_request` 의 **legacy-disabled 게이트** — 단일 요청, 오류 봉투. **로그를 남기지 않는다.** stdio 와 HTTP 가 **공유**한다 | legacy 비활성 | modern-only 전용 |
| 3 | HTTP 계층의 **배치 배열 거부** — 원소 처리 전에 400 + -32600 | legacy 비활성, **또는 요청에 modern 버전 헤더**, 또는 배열 원소에 modern 표식(modern `_meta`·`server/discover`·비-dict `_meta`) | modern-only 에서 **배열 전량**, 그 밖의 구성에서는 **modern 헤더가 붙었거나 modern 표식 원소가 있는 배열만** |
| 4 | HTTP 계층의 **legacy 형상 알림 거부** — 빈 바디 400. **응답 본문이 없어 본문 식별로는 잡히지 않는다** | legacy 비활성 | modern-only 전용 |
| 5 | HTTP 계층의 **비객체 scalar 바디 거부** — 400 + -32600 | legacy 비활성 | modern-only 전용. dual·legacy-only 에서 같은 바디는 이 **표의 지점들 밖에서 500** 이 된다(#250 이 남긴 기존 동작이며 이 문서의 범위 밖) |
| 6 | HTTP 계층의 **헤더 검증 거부** — 일반 요청은 -32020 + 400, **알림은 빈 바디 400**(오류 코드가 실리지 않는다) | 빌드 내장 modern 버전 상수로 판정하며 활성 구성을 **조회하지 않는다** | **전 구성** |
| 7 | **JSON 파싱 실패 거부** — HTTP 400 + -32700, stdio 는 `_handle_raw` 의 동일 -32700 | 활성 구성을 **조회하지 않는다** | **전 구성**. **표의 다른 지점 전부보다 앞선다**. 귀속은 **era 미상** — `method` 도 `_meta` 도 읽을 수 없다 |

6번은 헤더 검증 **전반**이다 — (a) modern 헤더가 붙은 legacy 바디, (b) 헤더가 **없는** modern 바디(예: `_meta` 없는 `server/discover`), (c) 헤더가 어긋난 modern 바디를 모두 거부한다. **부분 이행 소비자의 신호**(헤더는 modern 으로 바꿨는데 바디는 아직 legacy)는 (a) 에만 해당하므로, 6번에 계수기를 달면 **modern 클라이언트의 헤더 실수가 그 신호에 섞인다**. 귀속 원칙(바디가 era 의 단일 출처)이 이 셋을 이미 올바르게 가른다. **알림 변형**은 빈 바디 400 이라 4번과 같은 사각지대를 갖는다(본문 식별로는 잡히지 않는다).

이 표의 각 행은 실측으로 확인했다. 재현은 §7 의 명령과 `tests/test_http_app_modern_only.py` 의 구성 분리 계약을 본다.

**stdio 는 별도 거부 지점이 아니다.** 2번 게이트를 HTTP 와 공유하므로 전송 축은 지점이 아니라 **라벨**(stdio / HTTP)로 구분해야 한다. 라벨 없이는 stdio 몫을 분리할 수 없고, 엣지 계측만 두면 stdio 가 통째로 누락된다.

프록시의 4xx 비율에는 인증 실패·헤더 검증·modern 바디 오류가 섞여 legacy 거부를 분리해낼 수 없다. 따라서 "카나리 기간에 사고가 없었다"를 데이터로 말할 수단이 지금은 존재하지 않는다.

**판정 가능하게 만드는 세 갈래 (사용자 결정)**:

- (i) **위 재도출 절차로 얻은 지점 전량에 로그 또는 카운터를 추가한다.** 서버 게이트 하나만으로는 부족하다 — 덮지 않은 지점이 있으면 실제 legacy 시도가 있었는데도 "거부 0" 으로 판정하게 된다. 조회식과 집계 범위를 함께 정의한다. 안 A 의 era 계수와 같은 축이므로 함께 도입하는 것이 자연스럽다.
- (ii) **엣지에서 계측을 지정한다.** 서버 코드를 그대로 두는 대신 프록시·게이트웨이에서 거부를 분리한다. 다만 **4번과 6번의 알림 변형**은 빈 바디라 응답 본문으로 식별할 수 없고 **stdio 트래픽은 엣지를 지나지 않아 2번의 stdio 몫이 통째로 누락**되므로, 이 갈래는 그 표면들을 구조적으로 관측하지 못한다.
- (iii) **계측을 도입하지 않는다.** C4 를 "사용자 문의로 드러난 breakage 없음"이라는 약한 조건으로 낮추고, 그것이 조용히 실패하는 미관측 소비자를 보호하지 못한다는 사실을 명시적으로 수용한다.

어느 갈래든 **관측하지 못하는 표면을 이름으로 적어 두는 것**이 필수다. "거부 0" 은 관측 범위 안에서의 0 이지 부재의 증명이 아니다.

(i) 또는 (ii) 를 택하면 함께 확정할 것: **성공 신호**(거부 0 인가 허용 한계 이하인가), **허용 한계**(C2 에서 "포기"로 분류된 소비자의 거부는 신호를 깨지 않는다), **판정 주기**(이 값이 C 의 하한을 정한다).

### "legacy 0" 의 정의 (관측을 채택할 경우)

**귀속 원칙**: legacy 버킷에는 **era 를 legacy 로 판정할 수 있는 요청만** 넣는다. era 판정은 `method`(문자열)와 `params._meta` 를 읽어야 성립하므로, **그것을 읽기 전에 거부되는 요청은 era 미상**이다. 근거는 실측이다 — `method` 가 없으면 modern `_meta` 를 실은 바디도 `_meta` 없는 바디와 **똑같이** -32600 을 받는다. 그 지점에서 두 세대는 구별되지 않으므로 legacy 로 세면 modern 클라이언트의 malformed 요청을 legacy 로 오분류한다.

**지점별 귀속은 계측 설계가 정한다.** 이 문서는 원칙까지만 고정한다 — 미리 배정하면 틀린 표가 정본으로 남는다. 판정이 자명하지 않아 **귀속 미정**으로 남기는 곳은 셋이다: 알림 경로의 `method` 부재(같은 형상이 `id` 유무로 다른 지점에서 거부된다), 배치 배열의 modern 표식 유무(modern-only 구성에서는 modern 표식이 붙은 배열까지 전부 거부된다), 비객체 scalar 바디(`method` 도 `_meta` 도 읽을 수 없다).

**계수 지점과 단위는 이 문서가 확정하지 않는다.** 계측 구현이 위 절차로 재도출해 정한다 — 이 문서를 검증하는 과정에서 정확한 계수 모델을 확정하려는 시도가 **네 번 연속** 코드의 다른 구석에 깨졌다. 표는 오늘 시점 스냅샷일 뿐이며, 고정 목록에 성공 조건을 매면 누락된 지점이 있어도 "거부 0" 으로 판정된다. 대신 계측 설계가 **반드시 만족해야 하는 불변식**을 고정한다.

**불변식** (각각 실제로 깨졌던 항목이다):

1. **계수 축은 둘 이상이어야 한다.** era 가 확정된 요청의 era 계수 하나로는 부족하다 — 그 계수 지점에 **도달하지 못한 채 종결되는** 요청이 있고(헤더 검증 거부, `method` 부재 거부, 파싱 실패), 그런 요청만 보내는 소비자가 있으면 거짓 "legacy 0" 이 난다.
2. **축의 경계는 "그 계수 지점에 도달했는가"로 잡는다.** "era 판정 여부"로 잡으면 안 된다 — HTTP 계층이 `is_modern_request` 를 `handle_request` 와 **별도로** 호출하므로 era 는 확정됐는데 계수 지점에는 못 간 요청이 생긴다.
3. **종결 형태는 반환만이 아니다.** 무응답(`None`), 202(빈 배치, 전원 무효 알림 배치), 예외 종료(dual·legacy-only 의 비객체 바디 500)까지 종결 경로다.
4. **축과 귀속은 별개다.** 축은 "어디서 잡혔는가", 귀속은 "어느 era 인가"다. 주 계수 지점 전에 종결된 요청도 바디로 era 를 읽을 수 있으면 **판정된 era(legacy 또는 modern)로 귀속한다** — 전부 era 미상도 아니고 전부 legacy 도 아니다.
5. **한 요청은 한 번만 세어져야 한다.** era 판정 이후의 거부(2번 게이트)는 era 계수에 이미 잡히므로 다시 세지 않는다.
6. **"legacy 0" 은 모든 축을 포함한다.** 어느 한 축만 0 이어도 부족하다.

**알려진 함정** (계측 설계가 각각 답을 정해야 한다):

- **빈 배치** — 원소 0 으로 202 종결. 0 건인가 1 건인가.
- **전원 무효 알림 배치** — 원소별인가 외부 1건인가. 이중으로 세지 않아야 한다.
- **통째로 거부된 배치의 계수 단위** — 배열 1건인가 원소 N건인가. 그 원소들은 era 판정을 받은 적이 없다.
- **배치 중간 예외** — `[유효한 요청, 비객체 원소]` 는 앞 원소를 **처리한 뒤** 뒤 원소에서 예외가 나 500 으로 끝난다. 이미 처리된 원소와 바깥의 배치 예외를 각각 어떻게 셀지, 이중으로 세지 않을지 정해야 한다.
- **정상 처리된 배치의 원소별 계수** — 원소가 각각 주 계수 지점을 지나므로 원소별이 자연스럽지만 위 배치 함정들과 한 규칙으로 묶이지 않는다.
- **dual·legacy-only 의 비객체 바디 500**.
- **era 판정 이후 거부의 중복**.
- 6번(헤더 검증 거부)의 귀속은 **원칙이 그대로 적용된다**: era 의 단일 출처는 요청 바디이고 헤더는 era 판정에 쓰지 않으므로(`docs/mcp-protocol-compat.md` 의 era 모델), 유효한 문자열 `method` 를 가진 `_meta` 없는 바디는 modern 헤더가 붙어도 **legacy** 다. **예외 하나**: `server/discover` 는 method 이름만으로 modern 이므로 `_meta` 가 없어도 legacy 가 아니다(era 판정 규칙에서 이름만으로 modern 이 되는 method 는 이것뿐이다). `method` 가 없거나 비문자열인 변형만 era 미상이다. 미정 항목이 아니다.
- 알림도 계수 대상이다.
- 라벨: 전송 축(stdio / HTTP)을 라벨로 붙인다.
- 집계 범위: stdio 와 HTTP 를 포함한 모든 서빙 표면.
- **"legacy 0" 의 뜻**: **모든 축에서** legacy 버킷이 0 이고 **동시에** era 미상 버킷이 검토되어 그 안에 legacy 소비자가 없음이 확인된 상태. 미상 버킷을 조용히 무시하면 malformed 바디를 보내는 legacy 소비자가 0 뒤에 숨는다. 미상 요청의 출처를 어떻게 판별할지(요청 출처, 토큰 주체 등)도 계측 설계 항목이다.
- 재기동 취약성: 계수는 프로세스 메모리에 산다. "legacy 0" 은 **재기동 이후 연속 가동 시간이 W 이상인 구간에서의 0** 으로 정의하거나, 종료 시 값을 내보내야 한다.

## 7. 롤백 경로

`MCP_PROTOCOL_VERSIONS` 를 미설정으로 되돌리고 재기동한다. 코드 원복은 필요 없다.

**코드가 실제로 삭제된 뒤에는 이 레버가 사라진다.** 따라서 레버가 유효한 modern-only 운영 기간을 거친 뒤에만 삭제한다. 순서를 뒤집으면(삭제 먼저, 관찰 나중) 롤백이 재배포가 된다.

### 재현 (레버가 작동하는지 확인)

```bash
# modern-only 와 dual 구성의 계약 분리
.venv/bin/pytest tests/test_http_app_modern_only.py -q

# 구성 파싱 자체 (미지 버전과 구분자만 있는 값은 기동 거부)
.venv/bin/python -c "
from opencrab.mcp.protocol import parse_enabled_versions as p
print(p('2026-07-28'))          # modern-only
print(p(None))                  # 전체 (기본값)
"
```

## 8. 이 문서가 닫히는 조건

**채택한 경로에서 적용되는 조건**(§4 — 안 A 는 C1~C4, 안 B 는 C1·C2·C4)이 전부 충족되고 제거가 실행되면 이 문서는 제거 PR 의 근거 기록이 되며, `docs/mcp-protocol-compat.md` 에서 legacy 절이 삭제된다. 그 전까지 이 문서는 **미결 상태**다.
